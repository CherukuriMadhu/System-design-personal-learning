# Singleton Pattern

## 1. Definition

> **Singleton Pattern ensures that a class has only one instance/object and provides a way to access that same object whenever it is needed.**

In simple words:

```text
Class → Only ONE object

obj1 ──┐
       ├──> Same object
obj2 ──┘
```

Normally:

```python
obj1 = Database()
obj2 = Database()
```

creates **two different objects**.

With Singleton:

```python
obj1 = Database()
obj2 = Database()
```

both variables point to the **same object**.

---

# 2. Real-World Examples

Common examples where a single shared instance can make sense:

* **Logger** → one centralized logging service
* **Configuration manager** → one application configuration
* **Cache manager** → one shared cache
* **Database connection manager** → potentially one shared manager/pool

> Note: In real production systems, especially for database connections, you often use a **connection pool** rather than literally one database connection.

---

# 3. First Understand the Normal Behavior

Consider:

```python
class Database:
    pass


db1 = Database()
db2 = Database()

print(db1 is db2)
```

Output:

```text
False
```

Why?

Because:

```text
Database()
    ↓
Object 1 → db1

Database()
    ↓
Object 2 → db2
```

Every call to:

```python
Database()
```

normally creates a new object.

---

# 4. How Does Singleton Stop This?

We need to control **object creation**.

In Python, the important method here is:

```python
__new__()
```

### `__new__()` vs `__init__()`

This is an important interview question.

### `__new__()`

Responsible for:

> **Creating and returning the object.**

### `__init__()`

Responsible for:

> **Initializing the object after it has been created.**

Think:

```text
Database()
   ↓
__new__()
   ↓
Object created
   ↓
__init__()
   ↓
Object initialized
```

For Singleton, we need to control the **creation**, so we use `__new__()`.

---

# 5. Basic Singleton Code

```python
class Singleton:

    _instance = None

    def __new__(cls):

        if cls._instance is None:
            cls._instance = super().__new__(cls)

        return cls._instance
```

Let's understand **every line**.

---

## Line 1

```python
class Singleton:
```

We create a class called `Singleton`.

---

## Line 2

```python
_instance = None
```

This is a **class variable**.

Initially:

```text
_instance
   ↓
None
```

It means:

> We haven't created our Singleton object yet.

---

# 6. What is `__new__()`?

```python
def __new__(cls):
```

`__new__()` is called when Python needs to create an object.

Here:

```python
obj1 = Singleton()
```

Python internally needs to create a `Singleton` object.

So `__new__()` gets called.

---

# 7. What is `cls`?

Inside:

```python
def __new__(cls):
```

`cls` refers to the class itself.

Here:

```python
Singleton()
```

means:

```text
cls → Singleton
```

So:

```python
cls._instance
```

means:

```python
Singleton._instance
```

---

# 8. The Important Condition

```python
if cls._instance is None:
```

Initially:

```python
Singleton._instance = None
```

Therefore:

```python
if None is None:
```

is `True`.

So Python enters the `if`.

---

# 9. Creating the Object

```python
cls._instance = super().__new__(cls)
```

This is the most confusing line.

Let's break it down.

### `super()`

`super()` allows us to access the parent class implementation.

Here:

```python
super().__new__(cls)
```

calls Python's normal object creation mechanism.

It creates the actual object.

Then we store it:

```python
cls._instance = ...
```

So now:

```text
Singleton._instance
       ↓
   Object #1
```

---

# 10. Return the Object

```python
return cls._instance
```

So:

```python
obj1 = Singleton()
```

gets:

```text
obj1
 ↓
Object #1
```

And:

```text
Singleton._instance
 ↓
Object #1
```

Both refer to the same object.

---

# 11. What Happens the Second Time?

Now:

```python
obj2 = Singleton()
```

Again:

```python
__new__()
```

is called.

But now:

```python
cls._instance
```

is **not `None`**.

It contains:

```text
Object #1
```

Therefore:

```python
if cls._instance is None:
```

is:

```text
False
```

So Python doesn't create another object.

It simply executes:

```python
return cls._instance
```

Therefore:

```text
obj1 ─────────┐
              ↓
           Object #1
              ↑
obj2 ─────────┘
```

# 12. Complete Example

```python
class Singleton:

    _instance = None

    def __new__(cls):

        if cls._instance is None:
            cls._instance = super().__new__(cls)

        return cls._instance


obj1 = Singleton()
obj2 = Singleton()

print(obj1)
print(obj2)

print(obj1 is obj2)
```

Output:

```text
<__main__.Singleton object at ...>
<__main__.Singleton object at ...>
True
```

The memory addresses may be displayed differently depending on the environment, but the important result is:

```text
True
```

---

# 13. Why `is` Instead of `==`?

We write:

```python
obj1 is obj2
```

not:

```python
obj1 == obj2
```

### `is`

Checks:

> Are these two variables referring to the **same object**?

### `==`

Checks:

> Do these two objects have equal values?

For Singleton, we specifically want to verify that both variables refer to the **same object**.

Therefore:

```python
obj1 is obj2
```

is the appropriate check.

# 15. Singleton Logger Example

Now let's use a realistic example.

```python
class Logger:

    _instance = None

    def __new__(cls):

        if cls._instance is None:
            cls._instance = super().__new__(cls)

        return cls._instance

    def log(self, message):
        print("LOG:", message)
```

Create two loggers:

```python
logger1 = Logger()
logger2 = Logger()
```

Use them:

```python
logger1.log("Application started")
logger2.log("User logged in")
```

Output:

```text
LOG: Application started
LOG: User logged in
```

Check:

```python
print(logger1 is logger2)
```

Output:

```text
True
```

So:

```text
logger1 ─────┐
             ↓
          Logger
             ↑
logger2 ─────┘
```

There is only **one Logger object**.

---

# 16. Why Do We Need Singleton?

Imagine an application has:

```text
10 different classes
```

and every class creates:

```python
Logger()
```

Without Singleton:

```text
Class A → Logger 1
Class B → Logger 2
Class C → Logger 3
Class D → Logger 4
```

With Singleton:

```text
Class A ──┐
Class B ──┤
Class C ──┼──→ One Logger
Class D ──┘
```

This provides a single shared instance.

---

# 17. Important Interview Question

### Q: Why do we use `__new__()` instead of `__init__()`?

Answer:

> `__new__()` controls the creation of an object, while `__init__()` only initializes an object after it has been created. Since Singleton needs to prevent the creation of multiple objects, we control `__new__()`.

This is a **very good interview answer**.

---

# 18. Another Important Question

### Q: Why do we use a class variable?

```python
_instance = None
```

Because the instance must be **shared across all calls** to the class.

If we wrote:

```python
def __init__(self):
    self._instance = None
```

then every object could have its own `_instance`, which defeats the purpose.

We need:

```text
Class
 |
 └── _instance
       |
       ↓
    One object
```

---

# 19. Biggest Disadvantages

Singleton isn't automatically a "good" design.

### 1. Global state

Many parts of the application can access the same object.

This can make dependencies less obvious.

### 2. Testing becomes harder

Suppose:

```python
class A:
    def __init__(self):
        self.logger = Logger()
```

Now `A` is tightly coupled to the global Singleton.

Testing may become more difficult because you can't easily replace the logger with a mock.

### 3. Can violate Single Responsibility Principle

A Singleton class is responsible for:

```text
Its actual job
+
Controlling its own unique instance
```

This can add another responsibility.

### 4. Multithreading concerns

The simple implementation can have issues if multiple threads try to create the first instance simultaneously.

For a basic interview, mention:

> "In a multithreaded environment, Singleton creation needs synchronization or another thread-safe mechanism."

---

# 20. Singleton vs Normal Class

| Normal Class                     | Singleton                    |
| -------------------------------- | ---------------------------- |
| Multiple objects allowed         | Only one object              |
| `Class()` can create new objects | Reuses existing object       |
| No special creation control      | Usually controls `__new__()` |
| Independent instances            | Shared instance              |

Example:

```python
class A:
    pass

a1 = A()
a2 = A()

print(a1 is a2)
```

```text
False
```

Singleton:

```python
s1 = Singleton()
s2 = Singleton()

print(s1 is s2)
```

```text
True
```

# 22. Remember This Simple Logic

The entire Singleton implementation comes down to:

```python
if instance_does_not_exist:
    create_instance()

return_existing_instance()
```

In Python:

```python
class Singleton:

    _instance = None

    def __new__(cls):

        if cls._instance is None:
            cls._instance = super().__new__(cls)

        return cls._instance
```

### Memorize this flow:

```text
Singleton()
    ↓
Is instance already created?
    │
    ├── NO → Create it
    │         ↓
    │      Store it
    │
    └── YES → Return existing one
```

That's the **core idea of Singleton**.
